The application

The application will be a two-page audiovisual experience. It will be adaptive for delivery on smartphones, desktop computers and other devices.

The content will be narrated stories backed with random video clips and a music score.

Each story will be in its own chapter. Each chapter will have a short title sequence, the story section and a short credits section.

The next story will automatically follow.

Story selection will be randomised, as will be the story order. The video clips behind each story will be randomly selected, as will their edit points. The background music will be randomly selected from a reasonably large library of tracks.

The assets

  1. UIDs of publicly available videos from YouTube, along with metadata including each video title and YouTube channel name. These will form the source for all the video clips shown behind each story.
  2. Narrated audio file recordings of my stories in MP3 or similar format, along with metadata including:
    • Story title
    • Date of publication
    • Length in seconds
    • Full text transcript
  3. Music files in MP3 format, which I have written and recorded. Metadata will include:
    • Track title

Pages

Public

The public-facing page will have three views with their associated areas and non-visible/audio components.

Views

  1. Title
  2. Main video
  3. Credits

The application will have the following view areas and components:

  1. Titles: Title text area.
  2. Titles: Video content area.
  3. Titles: Audio component.
  4. Main video: Volume control, including slider and mute.
  5. Main video: Transport controls, including pause, play and next.
  6. Main video: Presentation area.
  7. Main video: Music audio component.
  8. Main video: Narration audio component.
  9. Main video: Narration subtitles area.
  10. Credits: Text area with fields for:
    • Story title
    • Story author
    • Copyright date
    • Track title
    • Track author
    • Track copyright
  11. Credits: Video area.
  12. Credits: Music component.

Admin

The Admin page will have views which satisfy those of a CRUD-type application.

If possible, for the purposes of authentication and access, it will exist within the GitHub repository account scope where the application is hosted and use the GitHub authentication flow.

I assume some type of database will be used to hold records of uploaded content and its state.

  1. Authentication flow.
  2. Browse stories.
  3. Search stories.
  4. Edit story. Text input fields for editing metadata including:
    • Story title
    • Author
    • Copyright details (date widget)
  5. Delete story. Requires confirm/undo functionality. Incorporate into Browse/Search view. Use selection checkboxes in the list to facilitate multiple selections.
  6. Add story. Upload of audio file. Addition of story metadata values of:
    • Story title
    • Story author
    • Story copyright (date widget)
  7. Browse stories. Displays a listing of stories in title alphabetical order with a date added column. Has column sorting on story name and date added.
  8. Search stories. A subview of Browse stories. A text input with search and clear buttons. The search action invokes a redisplay of the browse stories listing.
  9. Browse tracks. Displays a listing of tracks in title alphabetical order with a date added column. Has column sorting on track name and date added.
  10. Search tracks. A subview of Browse tracks. A text input with search and clear buttons. The search action invokes a redisplay of the browse tracks listing.
  11. Edit track. Allows editing of track metadata:
    • Track title
    • Track author
    • Track copyright (date widget)
  12. Delete track(s). Requires confirm/undo functionality. Incorporate into Browse/Search view. Use selection checkboxes in the list to facilitate multiple selections.
  13. Add track. Allows MP3 file upload and addition of track metadata:
    • Track title
    • Track author
    • Track copyright (date widget)
  14. Add CSV list of YouTube video 11-character UIDs.
  15. Browse UIDs. Table listing view with UID and date added columns.
  16. Search UIDs. A subview of Browse UIDs. A text input with search and clear buttons. The search action invokes a redisplay of the browse UIDs table listing.
  17. Delete UID(s). Requires confirm/undo functionality. Incorporate into Browse/Search view. Use selection checkboxes in the list to facilitate multiple selections.
